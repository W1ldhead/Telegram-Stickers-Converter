ТЗ: конвертер видео в стикеры Telegram
Задача
Программа для Windows превращает видео в готовый видеостикер Telegram в одно действие: перетащить файл, нажать «Конвертировать», получить .webm, который без ошибок принимает бот @Stickers.
Сейчас это цепочка из трёх программ: узнать разрешение исходника, пересчитать его так, чтобы большая сторона стала 512 px, выставить его в DaVinci Resolve, отрендерить, открыть результат в HandBrake, выбрать WebM, подобрать качество и отрендерить снова. Программа заменяет пересчёт разрешения, оба рендера и HandBrake целиком.
Монтаж и удаление фона, если они нужны, делаются заранее в видеоредакторе. Программа работает с уже готовым роликом.

Платформа и стек
Десктопное приложение для Windows 10/11 (x64), которое запускается из одного .exe без установки Python или ffmpeg.
Язык: Python 3.11+.
Интерфейс: PySide6 (Qt), drag-and-drop файлов в окно.
Обработка видео: ffmpeg и ffprobe в сборке с libvpx-vp9, вложены в программу.
Вызов ffmpeg через subprocess со списком аргументов, в фоновом потоке (QThread), чтобы окно не зависало. Консольное окно ffmpeg не показывается (CREATE_NO_WINDOW).
Сборка: PyInstaller.
Если Claude Code считает другой стек проще для сборки в один .exe, можно заменить, но требования к интерфейсу и результату остаются.
Интерфейс
Одно окно без вкладок, сверху вниз:
Зона «Перетащите видео сюда» и кнопка «Добавить файлы». Принимает mp4, mov, mkv, webm, avi, gif, сразу несколько файлов.
Список файлов. В строке: имя, длительность, fps, признак прозрачности, разрешение до и после («1920×1080 → 512×288»), статус (В очереди / Обработка / Готово, 241 КБ / Ошибка) и кнопка удаления из списка.
Для файла длиннее 3 с в его строке появляется выбор: «Первые 3 секунды» (по умолчанию), «Начать с … с» (поле ввода секунд), «Ускорить до 3 секунд».
Папка сохранения: поле и кнопка «Обзор». По умолчанию та же папка, что у исходника. Последний выбор запоминается между запусками.
Кнопка «Конвертировать», общий прогресс-бар и кнопка «Отмена».
После завершения — кнопка «Открыть папку».
Имя результата: <имя исходника>_sticker.webm. Если такой файл уже есть, добавляется _2, _3 и так далее; существующие файлы не перезаписываются. Язык интерфейса — русский.
Логика обработки
Каждый файл проходит одинаковые шаги; файлы обрабатываются по очереди.
Анализ (ffprobe). Ширина, высота, длительность, fps, кодек, pix_fmt, наличие звука. Учитывать метаданные поворота: видео с телефона 1920×1080 с поворотом 90° считается вертикальным 1080×1920.
Масштаб. Большая сторона становится ровно 512 px, меньшая считается по пропорциям, без полей и растягивания. Видео меньше 512 px увеличивается. Фильтр: scale=512:512:force_original_aspect_ratio=decrease:flags=lanczos.
Длительность. Итог не длиннее 2,95 с (запас на округление в метаданных; значение — константа в коде). «Первые 3 секунды» и «Начать с» — обрезка через -ss и -t; «Ускорить» — setpts=PTS*2.95/<длительность>.
Частота кадров. Выше 30 fps — привести к 30; иначе оставить исходную. Переменная частота приводится к постоянной (фильтр fps).
Звук. Всегда удаляется (-an).
Прозрачность. Если у исходника есть альфа-канал (ProRes 4444, PNG в MOV, WebM с альфой, pix_fmt с «a»), на выходе yuva420p, иначе yuv420p. Для входного WebM VP9 декодер задаётся явно (-c:v libvpx-vp9 перед -i), иначе ffmpeg теряет альфу.
Кодирование. libvpx-vp9 в режиме постоянного качества (CRF, -b:v 0), контейнер WebM. Значение CRF подбирается автоматически (следующий раздел).
Проверка результата. ffprobe по готовому файлу сверяет все пункты таблицы требований. Нарушение — статус «Ошибка» с причиной.
Пример итоговой команды для обычного mp4:
ffmpeg -y -i input.mp4 -t 2.95 -an -vf "scale=512:512:force_original_aspect_ratio=decrease:flags=lanczos,fps=30" -c:v libvpx-vp9 -crf 30 -b:v 0 -row-mt 1 -pix_fmt yuv420p output.webm
Подгонка под 256 КБ
Программа сама находит наилучшее качество, при котором файл укладывается в лимит, — вручную ничего подбирать не нужно.
Лимит: 262 144 байта (256 × 1024); целевой размер с запасом — не больше 260 000 байт.
Двоичный поиск CRF в диапазоне 15–63: ищется наименьший CRF (лучшее качество), при котором файл в лимите. Это до 6 коротких проходов; первая проба — CRF 30.
Если не влезает даже CRF 63, частота кадров снижается до 24, затем до 20, и поиск повторяется.
Если не влезает и так — статус «Ошибка: не укладывается в 256 КБ» с лучшим достигнутым размером.
В статусе готового файла показываются итоговый размер и fps, если она была снижена.
Промежуточные файлы пишутся во временную папку и удаляются; в папку сохранения попадает только итоговый файл.
Ошибки и граничные случаи
Ошибка в одном файле не останавливает обработку остальных; каждая показывается понятным текстом на русском.
Файл не читается как видео → «Не удалось прочитать файл» в строке файла.
ffmpeg завершился с ошибкой → статус «Ошибка», последние строки вывода ffmpeg во всплывающей подсказке.
ffmpeg.exe или ffprobe.exe не найдены → сообщение при запуске программы.
Нет прав на запись в папку → сообщение до начала обработки.
Пути с кириллицей, пробелами и скобками работают (аргументы передаются списком, без склеивания строки).
«Начать с … с» дальше конца видео → поле подсвечивается, конвертация этого файла не запускается.
Отмена → текущий процесс ffmpeg останавливается, недописанный файл удаляется, уже готовые остаются.
Закрытие окна во время конвертации → то же, что отмена; фоновых процессов ffmpeg не остаётся.
Сборка и поставка
Результат — один StickerMaker.exe, который запускается двойным кликом на чистой Windows.
Структура проекта: main.py, ui/ (окно), core/ (анализ, кодирование, подгонка размера), bin/ (ffmpeg.exe, ffprobe.exe), README.md. Логика в core/ не зависит от интерфейса и запускается из командной строки для проверки.
ffmpeg: готовая сборка для Windows (gyan.dev или BtbN). Перед включением в проект проверить, что в ней есть libvpx-vp9 (ffmpeg -encoders).
PyInstaller в режиме --onefile --windowed, ffmpeg и ffprobe вложены в exe; путь к ним определяется и при запуске из исходников, и из собранного exe.

Критерии приёмки
Работа считается готовой, когда выполнены все проверки.
☐ mp4 1920×1080, 10 с, со звуком → 512×288, не длиннее 3 с, без звука, VP9, до 256 КБ.
☐ Вертикальное видео с телефона (с метаданными поворота) → 288×512, не лежачее.
☐ Маленькое видео 300×200 → 512×341.
☐ Видео 60 fps → 30 fps.
☐ MOV ProRes 4444 с прозрачным фоном → фон остаётся прозрачным в Telegram.
☐ Все три режима для длинного видео (первые 3 секунды, с заданного момента, ускорение) дают корректный результат.
☐ Динамичное видео, которое при CRF 30 больше 256 КБ, автоматически укладывается в лимит.
☐ Пачка из 5 файлов, один из них битый → 4 готовых стикера и одна понятная ошибка.
☐ Путь с кириллицей и пробелами работает.
☐ Каждый результат загружается в бота @Stickers без ошибок.
☐ exe запускается на Windows без установленных Python и ffmpeg, окно не зависает во время конвертации.
